How the Bot Service communicates: native route vs custom translator route

The Azure Bot Service is a registration resource, not a runtime hop. It tells Microsoft's Bot Channel Service which endpoint to POST to and which App ID the traffic is signed for. For private Foundry, both runtime routes need a public traffic router with TLS termination and private forwarding; the routes differ only in what sits behind that router.

Public traffic router applies to both runtime routesFor a private Foundry endpoint, the native and custom routes both need a public entry point that routes inward and a component that terminates TLS. This can be one component or two: firewall, load balancer, CDN, Application Gateway, APIM, or another appliance.
1
What the Bot Service actually doesIt's registration only: it stores the msaAppId and messaging endpoint and enables the Teams channel. The Bot Channel Service reads it to know where to POST and which App ID the JWT is signed for.
2
The one real differenceNative: the router forwards straight to Foundry's built-in activity protocol - no translation code. Custom: it forwards to a container we own that translates to the Responses API, giving us control over delegated tokens and consent.
