PRIVATE FOUNDRY → MICROSOFT TEAMS · END-TO-END, NETWORK-ISOLATED

High-Level Architecture

Publishing network-isolated Azure AI Foundry agents to Microsoft Teams without exposing Foundry to the public internet. A Teams message travels through Entra + Azure Bot Service, into a private APIM front door, then to the private Foundry endpoint via one of two publishing approaches — the custom translator (per-user MCP auth) or the REST API native channel (fastest path).

Rule of thumb: agent grounds only on data Foundry reaches under its own identity (AI Search, service-account MCP) → ④ REST API native channel. Agent has an MCP tool that must act as the signed-in user (per-user OBO / delegated data) → ③ custom translator. Both keep Foundry private and route through APIM.
