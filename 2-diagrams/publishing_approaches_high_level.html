PRIVATE FOUNDRY TO TEAMS

Two ways to publish a private Foundry agent

The key choice: do we own the Teams integration, or does Foundry?

Private Foundry agentBoth options preserve the private endpoint and need a secure public path for Teams traffic.

Custom Teams bridge

Shared container + IaC

Our platform connects Teams to Foundry through APIM and a shared translator.

  • ✓Teams → Bot Service → APIM → shared router → Foundry.
  • ✓We control the Teams experience and routing.
  • ✓Supports custom delegated-token handling.
  • ✓Produces a Teams app package to distribute.

Native Foundry publish

REST API + agent catalog

Foundry publishes the agent directly to Teams and Microsoft 365 Copilot.

  • ✓Teams/Copilot → channel adapter → ingress → Foundry.
  • ✓Foundry owns the activity protocol.
  • ✓Agent appears in the Microsoft 365 catalog.
  • ✓Less custom runtime to operate.
Choose customWhen Teams UX or user-token handling needs control.
Choose nativeWhen catalog publishing and lower operational ownership matter most.
Common requirementTLS, ingress routing, and private Foundry connectivity remain necessary.
